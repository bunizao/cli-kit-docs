---
title: "Ed Discussion MCP tool catalog"
description: "Every tool the Ed Discussion MCP servers expose, with its parameters, gating, and whether it writes to Ed."
---

This catalog lists the 27 tools the Ed Discussion Model Context Protocol (MCP) server provides, in the order it lists them. Descriptions are the exact text the server ships for each tool.

Every tool is listed on every surface — stdio (`edstem-mcp`), a self-deployed Worker, and the hosted `https://edstem.tuuhub.com/mcp` service. Gating happens when a tool is called, not when it is listed:

- `create_thread` and `reply_thread` post publicly to a course. They fail with `INSUFFICIENT_SCOPE` unless posting is allowed: `EDSTEM_ALLOW_POSTING=1` for stdio, `MCP_ALLOW_POSTING=1` for a self-deployed Worker, or the write scope granted during the hosted service's OAuth consent.
- `mark_lessons_read`, `submit_slide_answer` and `submit_slide` write too, but only require write access, not the posting flag. stdio and a self-deployed Worker grant write access to the token holder unconditionally; the hosted service still requires the same OAuth write scope that gates posting.
- The four `show_*` tools are read-only views. Hosts that support MCP Apps render them in the chat; other hosts get the same data as text. On stdio, `EDSTEM_WIDGETS=0` removes them from the list.

Alongside the views, the server offers a `teach_lesson` prompt. Give it a unit and words from a lesson title, and it reads the lesson and runs `show_lesson_guide` end to end.

See [Security](/mcp/security) for the full gating model. For the CLI equivalents, see [`/edstem/reference`](/edstem/reference/index).

### get_user

Who is signed in and the courses they can see. Use when a request is vague or you need to learn how this Ed site names its courses. Not for course details beyond id, code, name and status (same list as list_courses). Then pass a course id or code to any courseId argument. Cost: small.

Available on: stdio, self-deployed Worker, hosted. Read-only.

### list_courses

Enrolled courses with id, code, name and status; archived courses omitted unless includeArchived. Use when the user asks what they are enrolled in, or names a course you cannot resolve. Then use the id or the code exactly as returned as courseId. Cost: small.

<ParamField path="includeArchived" type="boolean" default="false">
  Also return courses Ed marks as archived; defaults to false.
</ParamField>

Available on: stdio, self-deployed Worker, hosted. Read-only.

### list_lessons

Compact lesson summaries for one course: id, title, module, type, state, progress. Use when the user asks which lessons, modules or weeks exist, or what is unfinished. Call without filters first; an empty list means the course has no Ed Lessons. Filters are case-insensitive; pass all or omit a filter to include every value. courseId accepts a numeric ID, a unit code, or part of the unit name. Then get_lesson for slides, list_lesson_files for downloads, mark_lessons_read to update progress. Cost: about 100 bytes per lesson.

<ParamField path="courseId" type="integer | string" required>
  Ed course ID, the unit code as Ed shows it, or part of the unit name.
</ParamField>

<ParamField path="lessonType" type="string">
  Exact lesson type, for example `"general"`. Use `"all"` or omit to include every type.
</ParamField>

<ParamField path="module" type="string">
  Module ID or case-insensitive text from the module name. Use `"all"` or omit to include every module.
</ParamField>

<ParamField path="state" type="string">
  Exact availability state, for example `"active"` or `"scheduled"`. Use `"all"` or omit to include every state.
</ParamField>

<ParamField path="status" type="string">
  Exact progress status: `"unattempted"`, `"attempted"`, or `"completed"`. Use `"all"` or omit to include every status.
</ParamField>

Available on: stdio, self-deployed Worker, hosted. Read-only.

### get_lesson

One lesson with its slides and slide content. Use when the user asks what a lesson says or you need a slide id. Not for downloadable files (list_lesson_files) or quiz questions (list_slide_questions). lessonId comes from list_lessons. Cost: large for long lessons.

<ParamField path="lessonId" type="integer" required>
  Ed lesson ID as returned by `list_lessons`.
</ParamField>

Available on: stdio, self-deployed Worker, hosted. Read-only.

### list_lesson_files

Ed-hosted downloadable files and direct resource links for one lesson, returned as resource links. Use when the user wants slides, PDFs or attachments. Not for external links inside lesson text (get_lesson). lessonId comes from list_lessons. Cost: small.

<ParamField path="lessonId" type="integer" required>
  Ed lesson ID as returned by `list_lessons`.
</ParamField>

Available on: stdio, self-deployed Worker, hosted. Read-only. Returns a JSON block plus one `resource_link` content item per file.

### list_thread_files

Ed-hosted downloadable files and direct resource links attached to one thread, including its answers and comments, returned as resource links. Use when the user wants attachments from a thread. threadId is the global id from list_threads. Cost: small.

<ParamField path="threadId" type="integer" required>
  Global thread ID as returned by `list_threads`.
</ParamField>

Available on: stdio, self-deployed Worker, hosted. Read-only. Returns a JSON block plus one `resource_link` content item per file.

### list_slide_questions

Quiz questions for one lesson slide with one-based choice numbers. Use when the user wants to see or answer a quiz. slideId comes from get_lesson. Then submit_slide_answer per question, then submit_slide. Cost: small.

<ParamField path="slideId" type="integer" required>
  Ed slide ID as returned by `get_lesson`.
</ParamField>

Available on: stdio, self-deployed Worker, hosted. Read-only.

### list_slide_responses

Saved quiz responses for one lesson slide. Use when the user asks what they answered or whether a quiz is submitted. slideId comes from get_lesson. Cost: small.

<ParamField path="slideId" type="integer" required>
  Ed slide ID as returned by `get_lesson`.
</ParamField>

Available on: stdio, self-deployed Worker, hosted. Read-only.

### get_slide

One lesson slide with its content as structured data. Use when you already have a slide id and need only that slide rather than the whole lesson. slideId comes from get_lesson. For prose, prefer read_slide. Cost: small to medium.

<ParamField path="slideId" type="integer" required>
  Ed slide ID as returned by `get_lesson`.
</ParamField>

Available on: stdio, self-deployed Worker, hosted. Read-only.

### list_threads

Compact thread summaries for one course: id, number, title, category, answered state. Use when the user asks what is being discussed or wants a thread by title. Categories are hierarchical: category is top-level and subcategory is second-level, spelled as Ed shows them. Sort defaults to new; Ed may keep pinned threads first. Not for thread bodies (get_thread) or the user's own posts (list_activity). courseId accepts a numeric ID, a unit code, or part of the unit name. Cost: about 150 bytes per thread; use limit.

<ParamField path="courseId" type="integer | string" required>
  Ed course ID, the unit code as Ed shows it, or part of the unit name.
</ParamField>

<ParamField path="answered" type="boolean">
  Keep answered threads when true, unanswered when false; omit for both.
</ParamField>

<ParamField path="category" type="string">
  Exact top-level category.
</ParamField>

<ParamField path="subcategory" type="string">
  Exact second-level subcategory.
</ParamField>

<ParamField path="threadType" type="string">
  Exact thread type, for example `"question"` or `"post"`.
</ParamField>

<ParamField path="sort" type="string" default="new">
  `new`, `old`, `top`, or `hot`. Ed may keep pinned threads ahead of this order.
</ParamField>

<ParamField path="since" type="string">
  Only threads created at or after this time: an ISO date, an ISO datetime, or a relative offset such as `"7d"`, `"12h"`, or `"2w"`.
</ParamField>

<ParamField path="limit" type="integer" default="30">
  Maximum threads to return, capped at 100.
</ParamField>

<ParamField path="offset" type="integer" default="0">
  Threads to skip in the unfiltered Ed stream before filtering.
</ParamField>

Available on: stdio, self-deployed Worker, hosted. Read-only.

### search_threads

Threads in one course whose title or body contains every query word, case-insensitively. Use when the user asks about a topic rather than a thread number. Ed is paged client-side until limit threads match; accepts the same filters as list_threads. courseId accepts a numeric ID, a unit code, or part of the unit name. Then get_thread or read_thread for the body. Cost: several Ed pages for rare words; use limit and since.

<ParamField path="courseId" type="integer | string" required>
  Ed course ID, the unit code as Ed shows it, or part of the unit name.
</ParamField>

<ParamField path="query" type="string" required>
  Words that must all appear, case-insensitively, in the thread title or body.
</ParamField>

<ParamField path="answered" type="boolean">
  Keep answered threads when true, unanswered when false; omit for both.
</ParamField>

<ParamField path="category" type="string">
  Exact top-level category.
</ParamField>

<ParamField path="subcategory" type="string">
  Exact second-level subcategory.
</ParamField>

<ParamField path="threadType" type="string">
  Exact thread type.
</ParamField>

<ParamField path="sort" type="string" default="new">
  `new`, `old`, `top`, or `hot`.
</ParamField>

<ParamField path="since" type="string">
  Only threads created at or after this time.
</ParamField>

<ParamField path="limit" type="integer" default="30">
  Maximum threads to return, capped at 100.
</ParamField>

<ParamField path="offset" type="integer" default="0">
  Threads to skip in the unfiltered Ed stream before filtering.
</ParamField>

Available on: stdio, self-deployed Worker, hosted. Read-only.

### get_thread

One thread with its answers and comments, compact. Use when the user wants what a thread says. threadId is the global id from list_threads or list_activity; for a course-local number such as #42 use get_course_thread. Cost: proportional to replies.

<ParamField path="threadId" type="integer" required>
  Global Ed thread ID as returned by `list_threads`; for the number shown inside a course use `get_course_thread`.
</ParamField>

<ParamField path="includeHtml" type="boolean" default="false">
  Also return Ed's XML content; the plain-text document is always returned.
</ParamField>

Available on: stdio, self-deployed Worker, hosted. Read-only.

### get_course_thread

One thread addressed by course and course-local number (the #N Ed shows), compact. Use when the user gives a thread number rather than a global id. courseId accepts a numeric ID, a unit code, or part of the unit name. Cost: as get_thread.

<ParamField path="courseId" type="integer | string" required>
  Ed course ID, the unit code as Ed shows it, or part of the unit name.
</ParamField>

<ParamField path="number" type="integer" required>
  One-based thread number as shown inside the course, the #N in the Ed thread list.
</ParamField>

<ParamField path="includeHtml" type="boolean" default="false">
  Also return Ed's XML content; the plain-text document is always returned.
</ParamField>

Available on: stdio, self-deployed Worker, hosted. Read-only.

### list_activity

The signed-in user's recent threads, answers and comments, optionally within one course. Use when the user asks what they posted or whether anyone replied. Not for other people's activity (list_threads). courseId is optional and accepts a numeric ID, a unit code, or part of the unit name. Cost: small.

<ParamField path="courseId" type="integer | string">
  Ed course ID or exact course code to filter by. Omit for every course.
</ParamField>

<ParamField path="filterType" type="string" default="all">
  `all`, `thread`, `answer`, or `comment`.
</ParamField>

<ParamField path="limit" type="integer" default="30">
  Maximum items, capped at 50.
</ParamField>

Available on: stdio, self-deployed Worker, hosted. Read-only.

### read_thread

One thread with its answers and comments as Markdown. Use when the user wants to read a thread rather than inspect its fields. Pass either threadId, or courseId plus the course-local number (the #N Ed shows). Cost: proportional to replies.

<ParamField path="threadId" type="integer">
  Global Ed thread ID; use instead of `courseId` and `number`.
</ParamField>

<ParamField path="courseId" type="integer | string">
  Ed course ID, the unit code as Ed shows it, or part of the unit name.
</ParamField>

<ParamField path="number" type="integer">
  Course-local thread number; requires `courseId`.
</ParamField>

Available on: stdio, self-deployed Worker, hosted. Read-only.

### read_lesson

One lesson and its slides as Markdown. Use when the user wants to read or summarise a lesson. lessonId comes from list_lessons. Not for files (list_lesson_files) or quiz questions (list_slide_questions). Cost: large for long lessons.

<ParamField path="lessonId" type="integer" required>
  Ed lesson ID.
</ParamField>

Available on: stdio, self-deployed Worker, hosted. Read-only.

### read_slide

One lesson slide as Markdown. Use when the user wants to read a single slide. slideId comes from get_lesson. Cost: small to medium.

<ParamField path="slideId" type="integer" required>
  Ed lesson slide ID.
</ParamField>

Available on: stdio, self-deployed Worker, hosted. Read-only.

### mark_lessons_read

Mark lessons and their slides as read; writes progress. Use only when the user explicitly asks to mark lessons read or complete. queries are words that must appear in lesson or module names; no queries means every lesson in the course. courseId accepts a numeric ID, a unit code, or part of the unit name. Cost: one write per slide.

<ParamField path="courseId" type="integer | string" required>
  Ed course ID, the unit code as Ed shows it, or part of the unit name.
</ParamField>

<ParamField path="all" type="boolean" default="false">
  Mark every lesson in the course; required when `queries` is empty.
</ParamField>

<ParamField path="queries" type="string[]" default="[]">
  Case-insensitive substrings that must all appear in the lesson title or module name; at most 10. When `queries` is empty, `all` must be true to mark every lesson of the course.
</ParamField>

<ParamField path="delaySeconds" type="number" default="0">
  Seconds to pause after each slide, 0 to 10. Raise it to go easy on Ed.
</ParamField>

Available on: stdio, self-deployed Worker, hosted. Writes to Ed (marks progress). Requires write access, not the posting flag: unconditional on stdio and a self-deployed Worker, the OAuth write scope on hosted.

### submit_slide_answer

Save one-based choices for one quiz question; writes. Use only when the user has chosen the answer. questionId comes from list_slide_questions. Then submit_slide to finalise the slide. Cost: one write.

<ParamField path="questionId" type="integer" required>
  Ed question ID as returned by `list_slide_questions`.
</ParamField>

<ParamField path="choices" type="integer[]" required>
  One-based answer indexes as shown by `list_slide_questions`; pass several for multiple-selection questions.
</ParamField>

<ParamField path="amend" type="boolean" default="false">
  Overwrite an answer already saved for this question.
</ParamField>

Available on: stdio, self-deployed Worker, hosted. Writes to Ed. Requires write access, not the posting flag: unconditional on stdio and a self-deployed Worker, the OAuth write scope on hosted.

### submit_slide

Submit all saved answers for one quiz slide; writes and is usually final. Use only with explicit user intent after answers are saved. slideId comes from get_lesson. Cost: one write.

<ParamField path="slideId" type="integer" required>
  Ed slide ID whose saved answers are submitted, as returned by `get_lesson`.
</ParamField>

Available on: stdio, self-deployed Worker, hosted. Writes to Ed. Requires write access, not the posting flag: unconditional on stdio and a self-deployed Worker, the OAuth write scope on hosted.

### create_thread

Create a thread in one course; posts publicly as the token owner and cannot be removed from here. Use only when the user explicitly asks to post and has approved the title and body. body is Markdown and is converted to Ed's document format. courseId accepts a numeric ID, a unit code, or part of the unit name. Cost: one write.

<ParamField path="courseId" type="integer | string" required>
  Ed course ID, the unit code as Ed shows it, or part of the unit name.
</ParamField>

<ParamField path="title" type="string" required>
  Thread title shown in the course thread list.
</ParamField>

<ParamField path="body" type="string" required>
  Post body in Markdown. It is converted to Ed's document format before posting.
</ParamField>

<ParamField path="type" type="string" required>
  `question` to ask, `post` to discuss; `announcement` needs staff rights.
</ParamField>

<ParamField path="category" type="string">
  Exact top-level category for the course.
</ParamField>

<ParamField path="anonymous" type="boolean" default="false">
  Hide the author name from other students. Staff can still see it.
</ParamField>

<ParamField path="private" type="boolean" default="false">
  Post privately to course staff instead of the whole course.
</ParamField>

Available on: stdio, self-deployed Worker, hosted. Writes to Ed, publicly by default. Gated by the posting flag: `EDSTEM_ALLOW_POSTING=1`, `MCP_ALLOW_POSTING=1`, or the hosted service's write scope.

### reply_thread

Reply to one thread, or to one comment inside it; posts publicly as the token owner and cannot be removed from here. Use only when the user explicitly asks to reply and has approved the body. body is Markdown and is converted to Ed's document format. threadId is the global id. Cost: one write.

<ParamField path="threadId" type="integer" required>
  Global Ed thread ID to reply to.
</ParamField>

<ParamField path="body" type="string" required>
  Reply body in Markdown. It is converted to Ed's document format before posting.
</ParamField>

<ParamField path="toCommentId" type="integer">
  Reply under this comment of the thread instead of at the top level. The comment must belong to `threadId`.
</ParamField>

<ParamField path="as" type="string">
  `answer` or `comment`. Defaults to `answer` on question threads and `comment` elsewhere.
</ParamField>

<ParamField path="anonymous" type="boolean" default="false">
  Hide the author name from other students. Staff can still see it.
</ParamField>

<ParamField path="private" type="boolean" default="false">
  Post privately to course staff instead of the whole course.
</ParamField>

Available on: stdio, self-deployed Worker, hosted. Writes to Ed, publicly by default. Gated by the posting flag: `EDSTEM_ALLOW_POSTING=1`, `MCP_ALLOW_POSTING=1`, or the hosted service's write scope.

### list_modules

Lesson modules of one course with the number of lessons in each. Use when the user asks which weeks or modules exist, or to pick a module value for list_lessons. courseId accepts a numeric ID, a unit code, or part of the unit name. Cost: small.

<ParamField path="courseId" type="integer | string" required>
  Ed course ID, the unit code as Ed shows it, or part of the unit name.
</ParamField>

Available on: stdio, self-deployed Worker, hosted. Read-only.

### show_forum_catchup

Interactive catch-up view of one course forum: unread announcements, then the threads from the last days (default 14) that are new to the user or have new replies, each expandable in place. Use first when the user asks what they missed, what is new, or to catch up on a course; hosts without interactive views get the same list as text. Not for plain-text answers when the user asks for text (list_threads), or finding a topic (search_threads). courseId accepts a numeric ID, a unit code, or part of the unit name. Then add one or two sentences on what stands out; do not repeat the list. Cost: one to a few Ed pages.

<ParamField path="courseId" type="integer | string" required>
  Ed course ID, the unit code as Ed shows it, or part of the unit name.
</ParamField>

<ParamField path="days" type="integer" default="14">
  How many days back to look, from 1 to 60.
</ParamField>

Available on: stdio, self-deployed Worker, hosted. Read-only. Renders an interactive view in hosts that support MCP Apps and returns the same data as text elsewhere; `EDSTEM_WIDGETS=0` removes it from stdio.

### show_thread_activity

Interactive weekly chart of new threads in one course over the last weeks (default 12), stacked by category, with each week expandable to its busiest threads; announcements and pinned threads are excluded. Use when the user asks what people are asking about, when the forum gets busy, or how discussion changed over the term. Not for individual threads (list_threads) or plain-text answers when the user asks for text. courseId accepts a numeric ID, a unit code, or part of the unit name. Then name the one or two patterns worth noticing. Cost: up to ten Ed pages.

<ParamField path="courseId" type="integer | string" required>
  Ed course ID, the unit code as Ed shows it, or part of the unit name.
</ParamField>

<ParamField path="weeks" type="integer" default="12">
  How many weeks back to chart, from 1 to 26.
</ParamField>

Available on: stdio, self-deployed Worker, hosted. Read-only. Renders an interactive view in hosts that support MCP Apps and returns the same data as text elsewhere; `EDSTEM_WIDGETS=0` removes it from stdio.

### show_lesson_progress

Interactive progress view of one course's Ed Lessons: completed of total for each released module in release order, its unfinished lessons on click, and a count of modules not released yet. Use when the user asks what they are behind on, what is left, or how far through the lessons they are. Not for plain-text answers when the user asks for text (list_lessons). courseId accepts a numeric ID, a unit code, or part of the unit name. Then say where to start; do not repeat the numbers. Cost: one Ed request.

<ParamField path="courseId" type="integer | string" required>
  Ed course ID, the unit code as Ed shows it, or part of the unit name.
</ParamField>

Available on: stdio, self-deployed Worker, hosted. Read-only. Renders an interactive view in hosts that support MCP Apps and returns the same data as text elsewhere; `EDSTEM_WIDGETS=0` removes it from stdio.

### show_lesson_guide

Show a study guide you wrote for one lesson as a step-through card, then a short practice quiz that the user answers and the widget grades in place. Use when the user asks to be taught, walked through, or quizzed on a lesson or topic. First read_lesson; then pass 3 to 6 sections of 2 to 4 short points, and 3 to 6 multiple-choice practice questions of your own, each with its answer index, a one-line why, and the index of the section it tests. Never copy, answer or hint at the lesson's own Ed quiz questions: Ed marks them. Then say one line and let the user work; do not restate the guide. Cost: one Ed request.

<ParamField path="lessonId" type="integer" required>
  Ed lesson ID from `list_lessons`.
</ParamField>

<ParamField path="sections" type="array" required>
  The guide in teaching order: one to eight sections, each a short `title` and one to five `points`.
</ParamField>

<ParamField path="quiz" type="array" default="[]">
  Up to eight practice questions the assistant wrote, each with `question`, two to five `options`, the zero-based `answer`, a one-line `why`, and the `section` it tests. Never the lesson's own Ed quiz questions.
</ParamField>

Available on: stdio, self-deployed Worker, hosted. Read-only. Renders an interactive view in hosts that support MCP Apps and returns the same data as text elsewhere; `EDSTEM_WIDGETS=0` removes it from stdio.
