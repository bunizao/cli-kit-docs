`moodle download` saves what the course page offers. `dl` and `get` are aliases of the same command.

## What you can download

```bash
moodle download "UNIT week 7 slides"
moodle dl "UNIT week 5" --to ./week-5
moodle download 'https://moodle.example.edu/mod/resource/view.php?id=91234' --dest './Week 03/slides.pdf'
```

A reference is an activity id, a same-site Moodle URL, or a `UNIT TASK` phrase resolved the same way as [Daily use](/moodle/daily-use). It can name:

- one activity: a resource, every file in a folder, or the files attached to an assignment (its brief, datasets);
- a whole section, by phrase (`"UNIT week 5"`) or by section URL (`…/course/view.php?id=34637&section=5`), including child sections the page shows inside it;
- a single file link (`…/pluginfile.php/…`).

A URL on another host is refused. Quote URLs in zsh, where `?` is a glob character.

## Browse when you are not sure

```bash
moodle dl
moodle dl UNIT
```

With no argument at a terminal, `download` walks unit, then section, then item, the way the course page does. Type to filter and press Escape to go back a step. `moodle dl UNIT` starts at that unit's sections.

## Where files land

| Flag | Effect |
| --- | --- |
| `--to <directory>` | Save into this directory, created when missing. Without it, files land in the current directory. |
| `--dest <path>` | The exact path for the file, when the reference resolves to exactly one file. |
| `--force` | Download everything again and replace existing files. |

A file already at the destination is skipped, so rerunning a section after Ctrl+C or a dropped connection fetches only what is missing. The same document linked twice is saved once, and two different files with one name get a ` (2)` suffix.

`-o, --output <file>` is different: it writes the command's own output (the summary of what was saved) to a file, not the downloaded file.

```bash
moodle download "UNIT week 7 slides" --to ./downloads --json -o ./downloads/receipt.json
```

To see which files an activity holds before downloading, run `moodle activities show ID`; it lists the files `download` would save.

## Keep units in sync

`moodle sync` keeps one folder per unit in step with Moodle: resources, folder contents and assignment attachments, laid out by section. Pages and books are saved as single HTML files with their images embedded, so they read the same offline.

```bash
moodle sync --to ~/Units
moodle sync UNIT --to ~/Units
moodle sync --dry-run
```

The first form syncs every unit into its own subfolder, the second just one unit, and `--dry-run` reports what would change without writing anything.

- A rerun asks Moodle only whether each file changed, and usually downloads nothing.
- A changed file replaces your copy only when you have not edited it. An edited copy stays put and the new version lands beside it as `name (updated YYYY-MM-DD).ext`.
- Files removed from Moodle are reported and kept locally. A file you delete stays deleted until Moodle changes it.
- Each unit folder holds a `.moodle-sync.json` file that records which unit it mirrors, so you can rename or move the folder freely.

## Failure modes

- A reference that matches several items lists the candidates instead of guessing. At a terminal you pick one.
- Moodle returning a sign-in page instead of a file means the session expired. Run `moodle auth login`.
- An existing file is never overwritten without `--force`.

See [Errors and exit codes](/concepts/errors-and-exit-codes) for exit codes and the JSON error shape.
