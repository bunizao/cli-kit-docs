This page is written for an AI agent with terminal access, such as Claude Code or Codex. A person can hand it over in one line:

```text
Read https://unicorn.tuuhub.com/docs/ontrack/agent-setup.md and set up ontrack for me.
```

The rest of the page speaks to the agent.

## Your job

You are connecting the user's OnTrack account to the `ontrack` CLI. Take ownership of the setup. Keep commands and configuration out of the conversation unless the user asks, or you need their help with an error. Use the user's language.

If the user only asked to set up remote MCP and `ontrack auth status` already works, skip to [Offer remote access](#offer-remote-access).

Never ask the user for their university password, their authenticator secret, a session cookie or an access token, and never print one.

## Install

1. Check for Node.js 22.5 or newer with `node --version`, or for Bun with `bun --version`. If neither is available, tell the user and stop until one is installed.
2. Install the CLI with `npm install -g ontrack`, or `bun add -g ontrack`.
3. Confirm with `ontrack --version`.

## Point it at the user's site

Ask the user for their OnTrack site's address, for example `https://ontrack.example.edu`. This is not a secret.

Save only the site's root, with no path, query string or credentials, in `~/.config/ontrack-cli/config.yaml`:

```yaml
base_url: https://ontrack.example.edu
```

Setting `ONTRACK_BASE_URL` also works, but only for the current shell. Prefer the config file so later sessions keep it. See [Configuration](/ontrack/configuration).

## Get the user signed in

Sign-in needs the user's hands. Run `ontrack auth login --browser`: it opens a private browser window. Ask the user to sign in there and tick "Remember me", so later sessions renew without them. Wait for them to say it finished.

- If no Chrome, Edge, Brave or Chromium is installed, ask the user to run `ontrack auth login --paste` in their own terminal (in Claude Code, `! ontrack auth login --paste`) and paste the credentials it asks for. Never ask them to paste credentials into the chat.
- If `ontrack auth status --local` later shows `renewal_expires_at` under 24 hours away, ask the user to sign in to OnTrack in their browser or run `ontrack auth login` again.

See [Sign in](/ontrack/sign-in) for what each path does and stores.

## Verify

1. Run `ontrack auth status --json`. It should report an active session for the site you configured.
2. Run `ontrack courses list --json`. Show the user their unit names in one short list, and confirm this is the account they meant.

Do not report success until both commands work. See [Troubleshooting](/ontrack/troubleshooting) for specific errors.

## Install the agent skill

In Claude Code, run `claude plugin marketplace add bunizao/ontrack-cli`, then `claude plugin install ontrack-cli@ontrack-cli`. Elsewhere, run `npx skills add https://github.com/bunizao/ontrack-cli`. The skill teaches agents which `ontrack` command answers which request. See [Agent skills](/agents/skills).

## Offer remote access

After local verification succeeds, ask:

> Do you want to use OnTrack from Claude on the web, ChatGPT or your phone too? It needs a free Cloudflare account and takes about five minutes.

If they decline, finish with local access and mention that remote access can be added later.

If they want it, the user does three steps in a browser. Run everything else yourself, and wait for them at each of those steps.

1. Run `okta-auth --help`. If it is missing, install it with `npm install -g okta-auth-cli`.
2. Run `okta-auth setup`. It opens a page in the user's browser. Ask them to save their Okta username, password and authenticator secret there, and to tell you when the test sign-in passes. If they don't know their authenticator secret, the page explains how to get one. Never ask for any of it in chat, and never run `okta-auth export`.
3. Run `npx wrangler whoami`. If it is not signed in, run `npx wrangler login` and ask the user to approve Cloudflare in the browser it opens.
4. Run `ontrack mcp deploy --json`. It deploys the server, signs it in to OnTrack through Okta, and prints `url` and `pairing_code`.
5. Ask which AI app they use. Give them the `url` to add as a custom connector there, and the `pairing_code` to type on the approval page that opens. The code lasts ten minutes and approves one app. If it expires, or they want another app, run `ontrack mcp pair`.
6. Run `ontrack mcp status --json` and check that `session.username` is their account.

See [Remote MCP](/ontrack/mcp-server) for what the server can do and how it stays signed in.

## Finish

Tell the user, in two or three sentences, what now works and one thing to try, such as "Which tasks in UNIT are still not started?". Do not list commands unless they ask.
