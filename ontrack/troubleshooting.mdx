Every error goes to stderr; `--json` prints it in the same shape described in [Errors and exit codes](/concepts/errors-and-exit-codes). This page covers what you'll actually see and how to fix it. For the exact exit code and `error.code` behind each one, see [OnTrack CLI for scripts and agents](/developers/ontrack#error-codes-and-exit-codes).

## Diagnose with doctor

```bash
ontrack doctor
ontrack doctor --live --cookies
```

`doctor` checks that the session file can be read, whether a renewal path exists, which browser the CLI can open and whether your site's sign-in can be found. It prints the whole report and exits with code 3 when a check fails. `--live` also calls OnTrack with your session; `--cookies` also reads your everyday browsers' cookies, which can ask for OS permission. It never prints tokens or cookie values.

Credentials set in the environment or the config file override the session file. If `doctor` passes but commands still fail, remove an invalid override, then run `auth login`.

## Sign-in expiring soon

```text
OnTrack sign-in expires in about 9 hours. Sign in on the OnTrack website or run `ontrack auth login` to renew it.
```

The renewal credential is in its last 24 hours, and renewing the session doesn't extend it. Sign in to OnTrack in your everyday browser or run `ontrack auth login`. Once it has lapsed, the message says the sign-in has expired; run `auth login`. If you never ticked "Remember me", there's no renewal credential, so you'll be asked to sign in whenever the session expires.

## CLI browser problems

**No browser to open**

```text
No Chromium-family browser is installed.
```

`--browser` needs Chrome, Edge, Brave or Chromium. Install one, or sign in with `ontrack auth login --paste`.

**The browser closed before sign-in completed**

Another `ontrack` sign-in or renewal may be using the same private profile. Wait for it to finish, then retry.

**Timed out**

`Timed out waiting for sign-in.` means the window stayed open without a finished sign-in. Complete the sign-in, then retry. `Timed out renewing the session in the background browser.` means automatic renewal needs you: run `ontrack auth login`.

## Reading your everyday browser's cookies

These apply to `--reuse-browser` and `doctor --cookies`.

**Permission denied (`EPERM`/`EACCES`)**

```text
Permission denied while reading Chrome cookies (EACCES). In System Settings > Privacy & Security >
Files & Folders, enable Chrome for the terminal or app that launched ontrack, then retry.
```

Grant the listed permission (macOS) or rerun the terminal with access to the browser's profile directory (Linux/Windows), then retry. Or skip this path: `ontrack auth login --browser` never reads your everyday browser's files.

**macOS Keychain prompt not approved**

```text
macOS Keychain did not authorize Chrome cookie decryption. Approve the Touch ID prompt for
ontrack, then retry.
```

Approve the Keychain prompt when it appears; it can hide behind the terminal window.

**No cookies found**

If no browser has a usable session, `--reuse-browser` falls through to the one-time DevTools snippet described in [Sign in](/ontrack/sign-in#choose-a-sign-in-path).

## DevTools snippet problems

- **Waited too long.** The CLI waits 5 minutes for the snippet. Rerun `ontrack auth login --manual` and paste it promptly after signing in.
- **Pasted the snippet, nothing happened.** Paste it into the OnTrack tab that finished signing in, not another tab.
- **"Sign-in could not be completed."** The snippet didn't return a valid session. Rerun `ontrack auth login`.

## Session file errors

```text
Could not decrypt the authenticated session cache.
```

This, or `The session encryption key is unavailable.`, means `ontrack` can't read its encrypted session, usually because the OS key store refused access or the key was removed. The old file is kept. Run `ontrack auth login` to sign in again, and approve the key store prompt if one appears.

## Wrong base URL

```text
No base_url configured.
Set ONTRACK_BASE_URL or add base_url to ~/.config/ontrack-cli/config.yaml.
```

```text
Base URL must be the site root.
```

The first means nothing is configured yet — see [Install](/ontrack/install#point-it-at-your-site). The second means `base_url` has a path, query string or credentials in it; it must be exactly the site's origin, for example `https://ontrack.example.edu` with nothing after it.

## Ambiguous UNIT

```text
Unit UNIT matches multiple projects: 1041, 1187. Use a project ID.
```

This is a usage error, not a not-found error — the reference matched more than once. Rerun with one of the listed project IDs. See [Resolving UNIT](/ontrack/units-and-tasks#resolving-unit) for the matching order that produced the list.
