Each CLI ships a skill: a `SKILL.md` file that tells an agent when to use the tool and which command answers which request, without reading the whole `--help` tree first.

## Install in Claude Code

`moodle` and `ontrack` are Claude Code plugins. Each repository is also its own plugin marketplace:

```bash
claude plugin marketplace add bunizao/moodle-cli
claude plugin install moodle-cli@moodle-cli
```

```bash
claude plugin marketplace add bunizao/ontrack-cli
claude plugin install ontrack-cli@ontrack-cli
```

The `moodle-cli` plugin also starts a local MCP server, so Claude Code can use the Moodle tools without the CLI on `PATH`. The `ontrack-cli` plugin carries the skill alone, because `ontrack` has no MCP server.

## Install with the skills CLI

For Codex and other agents, install the skill alone:

```bash
npx skills add https://github.com/bunizao/moodle-cli
npx skills add https://github.com/bunizao/edstem-cli
npx skills add https://github.com/bunizao/ontrack-cli
```

`moodle skills add` runs the first command for you. `npx skills add` writes the skill under `.agents/skills/<name>/` in the current project and records what it installed in a `skills-lock.json` next to it, so a later run can tell whether the installed copy still matches its source.

`edstem skills generate` and `ontrack skills generate` rebuild the skill from the CLI's own commands. You need them only when you change a CLI's commands, not to install the skill.

## What a skill contains

Each skill is generated from its CLI's `commands --json` output, so it cannot drift from what the binary does. `moodle-cli` and `ontrack` live in `skills/<name>/` in their repositories and contain:

- A description that says when to use the skill, with requests phrased the way students ask them, and which requests belong to one of the other two tools.
- A table of what a person asks for, the command that answers it, and, for `moodle`, the matching MCP tool. `UNIT`, `TASK` and `SECTION` are placeholders, never real identifiers.
- Checklists for changes: dry-run, confirm, apply with `--yes`, read the result back. Submitting a Moodle assignment has its own checklist.
- A short list of rules, each with its reason: prefer the narrowest command, keep tokens out of replies, follow an error's hint.
- `references/commands.md`: every command with its arguments, options and whether it changes anything upstream, plus the exit codes.

`edstem-cli` still ships a single `SKILL.md` at the repository root with the command table inline.

<Info>
  All three repositories check in their tests that the committed skill matches the CLI's commands, so a release cannot ship a stale skill.
</Info>

## Codex

`moodle-cli` and `ontrack` each ship `agents/openai.yaml` next to their skill: a display name, a short description and a default prompt for Codex. `edstem-cli` does not ship one at this version.
