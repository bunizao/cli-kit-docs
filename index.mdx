cli-kit is three command-line tools — `moodle`, `edstem`, and `ontrack` — that give students, teaching staff, and the AI apps you connect terminal and MCP (Model Context Protocol) access to the learning platforms a university runs: Moodle, Ed Discussion and OnTrack. All three tools work the same way: the same commands, the same way of showing an error, the same confirmation before anything changes. What you learn running one applies to the others.

| Tool | npm package | Binary | Reaches | Auth model | MCP |
| --- | --- | --- | --- | --- | --- |
| [Moodle CLI](/moodle/index) | `moodle-cli` | `moodle` | Moodle | Browser session | Yes: local + remote |
| [Ed Discussion CLI](/edstem/index) | `edstem-cli` | `edstem`, `edstem-mcp` | Ed Discussion | API token | Yes: local + hosted |
| [OnTrack CLI](/ontrack/index) | `ontrack` | `ontrack` | OnTrack | Browser session or SAML snippet | No |

A fourth project, [unicorn](/unicorn/index), is not a CLI. It is a Worker you deploy to your own free Cloudflare account that remembers your Ed, Moodle, Canvas and Gmail content between sessions and gives your AI agent one place to read it.

Each tool only reaches what your own account can already see: `moodle` borrows the browser session you signed in with, `edstem` uses a personal API token you create yourself, and `ontrack` reuses a browser session or falls back to a SAML (Security Assertion Markup Language) sign-in. None of them create a service account or a new set of upstream permissions.
